# Verify the completed borrowed-update experiment

Run `bash scripts/verify_router_borrowed_updates.sh` after syncing. It defaults to the full borrowed-update run. Set `OPERA_BORROWED_ROUTER_RUN` if that run was saved under another root. This is a CPU-only check, without patient data, an optimizer step, or a new training run.

The verifier checks saved checkpoint model-init settings and the resolved run config both specify `unanchored_adapters` with both source banks. It verifies the readout implementation hash against the run's source-code provenance. It reconstructs the saved readout and linear risk head and applies one synthetic target-outcome horizon-BCE loss. Home and supported borrowed source matrices must receive nonzero gradients. The same source state under the anchored negative control must retain home gradients and zero borrowed gradients. The probe establishes gradient connectivity under the recorded configuration, not an improvement in clinical predictions or the historical source of each optimizer update.

The repository implementation uses live down/up parameters when `anchored=False`; gradient caching detaches the encoder representations for replay but leaves these source parameters live, and Adam includes them. Similar performance between the two completed conditions therefore does not itself indicate that the gradient toggle failed.

Adam epsilon is a small stabilizer added to the square-root gradient-second-moment denominator. The value 1e-6 is inherited broadly across BONSAI/OPERA neural training configurations, including pretraining, specialist fits, and router fits. [PyTorch AdamW](https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW.html) defaults to 1e-8. Neither value is universally optimal; source gradients can have a different scale from the head or encoder. The recorded outcome-source moments show strong epsilon attenuation, motivating the targeted matrix-only 1e-8 comparison while retaining 1e-6 for router/head/encoder groups.
