# Tuning embedding and clinical-score recipes

`python -m opera.run.prepare_available_plot_configs --analysis-config <analysis_inventory/analysis.yaml> --output-dir <new-config-directory>` creates both fully populated recipes from the server inventory. It selects the inventory's OPERA model (R_L fallback), seed 42, tuning predictions and the adjacent patient_embeddings.npz. A joint stage is added when its export exists. Unknown registry risk labels cause an explicit error. Config generation reads real metadata/outcome identifiers; it does not create patient data or train models.

The common map palette is Low / Intermediate / High. Low-intermediate and high-intermediate both map to Intermediate. Very-high maps to High. These are harmonized display strata, not interchangeable clinical risk definitions across indices. Raw category labels are retained in config_audit.json. For recorded indices with only categories, discrimination is consequently based on the coarsened three-level ordinal score. Computed scores retain their numeric discrimination scores.

Requested map endpoints, in order: infection_diagnosis_or_antimicrobial_use_composite (legacy name infections_all_definitions), overall_survival, anemia_g2plus, hospitalisation, creatinine_increased_g2plus. Only available endpoints are included; omitted ones are recorded. The gallery covers all available outcomes. Router correction vectors are not invented: the optional arrows require separate outcome-specific vector exports and shared/adapted checkpoint matching.

Clinical contrasts compare OPERA to every recorded index on the same scored patients, per disease (minimum 50 recorded patients) and pooled over recorded diseases. Available computed IPI and NCCN-IPI columns add comparisons. A common one-year overall-survival endpoint is used in this exploratory tuning recipe. This is a common-endpoint benchmark, not a reproduction of every index's original endpoint/horizon. Native-endpoint comparisons can be specified separately. IPI in DLBCL supplies manuscript panels if that exact registry value exists. Before publication, confirm score timing and applicability with actual registry provenance; the generated recipe explicitly records that these remain tuning-rehearsal assumptions.

Set OPERA_PAPER_EMBEDDING_CONFIG and OPERA_PAPER_CLINICAL_SCORE_CONFIG in .env.rehearsal to the two generated YAML paths, then launch a fresh rebuild. The generator requires the existing successful inventory, even when the subsequent analysis failed. Clinical and embedding tables are separate from the main performance analysis.
