# Final-data release and experiment gates (30 September 2026)

## What the first-line counts establish

The new first-line counts-only reconstruction gives 37,482 mapped patients;
the older population metadata gives 37,494. The source of the 12-patient
difference is not established. The count-only launcher did not rewrite the
mapped CSV consumed by the existing outcome and second-line scripts. Existing
model runs are therefore interpretable as v4 pilot results against their
original inputs, but these counts cannot be mixed into one final CONSORT.

## Gate 1: identify the change before rerunning expensive stages

On the data server, preserve the current mapped CSV and all v4 derived files.
Record paths, sizes, modification times and SHA-256 hashes for the old mapped
CSV, current first-line R revision, its external DALY-CARE loader/package,
patient and diagnosis tables, treatment table, CLL/MM seed tables, and any
RKKP/codebook inputs it loads. The input table paths are in
`opera/R/identification_first_line_treatment_v2.R` and include both `load_dataset`
calls and direct Parquet reads. Determine whether the older 37,494 artifact was
generated by the same script/options and input snapshots. Compare patient IDs,
index dates, fine/grouped cohorts and primary arms *on the server* between the
old mapped CSV and a new isolated candidate export. Export aggregate change
counts/reason categories only, not patient identifiers. Reconcile the 11-person
loaded-patient versus diagnosis-index difference separately. Do not infer the
cause from a 12-person count difference alone.

## Gate 2: freeze one coherent final source release

Given the planned new EHR-to-MEDS build, use a new immutable release directory,
not the v4 paths. Decide and document the clinical outcome issues in
`docs/ascertainment_review.md` before freezing labels: coverage/observation
rules, J01EE01 typo, fibrinogen units, leukocytosis naming, cutoff dates, and
composite execution order. Run the production first-line reconstruction into a
new directory and verify its mapped CSV against the count-only stages. Then
regenerate from *that exact file*: second-line treatment/TTNT exports, adverse
events, coverage gates, composites, survival/other derived outcome files,
population metadata and frozen split membership. Audit endpoint counts,
chronology, ID uniqueness, split dates and first-line linkage. Preserve the
temporal split rule unless a protocol change is explicitly agreed.

Build the final MEDS sequences as a separate but coordinated branch. A changed
first-line denominator alone does not necessarily require rebuilding every raw
EHR event, but a changed source extract or the planned final EHR-to-MEDS release
does. Freeze code, raw source manifests, vocabulary/token-ID map, numeric
binning, time encoding, subject IDs and sequence schema alongside the derived
cohort/label manifests. Check that the final sequences cover every labelled
patient and that all features precede each prediction index. Do not silently
reuse a v4 DAPT checkpoint if the vocabulary/numeric encoding contract changes.
Keep the pretraining population and cutoff distinct from the supervised cohort.

Only after these checks, recompute Table 1, CONSORT, cohort support and the
publication figures from the frozen release. Small-cell disclosure review is
required before exporting/publishing exact breakdowns.

## Gate 3: experiments and writing while data work proceeds

No blanket rerun of the historical architecture sweep is needed. Continue to
inventory the completed v4 validation results and use them to shortlist shared
BCE, endpoint-group low-rank BCE and pooled XGBoost. A PHAIR checkpoint
compatibility smoke test and the matched validation-metric implementation can
proceed independently of the final data build. Finish clinically vetting the
outcome definitions, treatment/cohort methods and source provenance now.

Once the coherent final release passes its audit, rerun the shortlisted models
and XGBoost on matched patients/eligibility/horizons, with fresh versioned
model roots. Then perform only decision-relevant ablations: a corrected,
minimum-support outcome-balancing test; router versus fixed-routing/continued-
source controls if the matched signal warrants it; and pooled-versus-single-
disease experiments for the disease-benefit analysis. Repeat key finalists over
seeds, lock the selection, and use held-out data once for final evaluation.
